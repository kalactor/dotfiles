# dotfiles

A Hyprland rice for Arch Linux: **SDDM**, **kitty**, **vim**, **Waybar**,
**SwayNC**, **rofi**, **wlogout**, **hyprlock**, **hellwal**. No Quickshell.

One wallpaper change recolors the desktop, and light/dark mode follows the
sun:

```bash
wall set ~/Pictures/walls/light/<image>.jpg
rice-mode status
```

Generated files (`colors.css`, `colors.rasi`, `colors.lua`, `colors.conf`,
`hyprlock-colors.conf`, `gtk.css`, `wallust.vim`, btop/cava themes,
`~/.config/kdeglobals`, `~/.config/Kvantum/WallustFlat/`,

`~/.cache/rice/telegram.tdesktop-theme`) are generated by
matugen/hellwal/`rice-contrast`/`kde-theme`/`telegram-theme`; do not edit them
by hand.  The `wallust.vim` and `WallustFlat` names are retained for
compatibility with the legacy engine.

## Install / re-stow

Package snapshots are in `pkglists/native.txt` and `pkglists/aur.txt`. Review
and install what you need first (the native list includes applications beyond
the rice). Then install the configuration into your home directory:

```bash
cd ~/dotfiles
stow hypr waybar kitty swaync rofi matugen hellwal wallust swayimg wlogout vim bash zsh bin gtk rice mpv chrome btop cava fastfetch dolphin telegram
mkdir -p ~/.config/systemd/user
stow --no-folding systemd
systemctl --user daemon-reload
systemctl --user enable --now rice-sun.timer
```

On a new profile, set the first wallpaper **before the next graphical login**
so the theme engine creates all initially empty color includes:

```bash
wall set ~/Pictures/walls/light/<image>.jpg   # or an image from .../dark/
./tests/smoke.sh                             # syntax, fixtures, fresh Stow restore
```

Rofi utilities need `libqalculate` for the calculator. The optional Seed4
Waybar module uses separately installed personal `seed4`/`seed4-toggle`
scripts; those are external and not required by the base rice. Telegram's
one-time activation is documented below.

`theme-apply` seeds Dolphin's global Details view on first run (stored in an
xattr); it never overwrites a view mode you have already chosen.

`system/` is deliberately not stowed; see `system/README.md`.

A minimal fastfetch summary is printed once per kitty window (the `.zshrc` and
`.bashrc` guards use `KITTY_WINDOW_ID`, so nested shells stay quiet).

The interactive shell is **zsh**. `zsh-autosuggestions`,
`zsh-syntax-highlighting`, `zsh-history-substring-search` and
`zsh-completions` come from the official Arch packages. Suggestion and
highlight colours are generated from the hellwal palette into
`~/.cache/rice/zsh-colors.zsh`; the prompt is still Starship. Editing uses
emacs keybindings (forced with `bindkey -e` because `EDITOR=vim` would
otherwise make zsh start in vi mode); `Delete` deletes a character,
`Ctrl+Delete` deletes the next word, `Ctrl+Backspace` deletes the previous
word, and `Ctrl+Left`/`Ctrl+Right` move by word.

## Theme engine

`wall` sets the hyprpaper wallpaper, then `theme-apply` runs **hellwal** with
`-l` or `-d`. Hellwal renders an image-driven 16-colour base palette into
`~/.cache/rice/hellwal/palette.env`. `rice-contrast` then computes the
composited terminal background from the wallpaper and the kitty/Hyprland
opacity stack, moves colours in OKLCH until they meet the contrast policy, and
re-renders every application template. The same stage can consume matugen or
wallust palettes when either alternative engine is selected. Then `theme-apply`
reloads the apps:

| Target | File |
|---|---|
| Hyprland borders | `~/.config/hypr/colors.lua` |
| Waybar | `~/.config/waybar/colors.css` |
| swayimg | `~/.config/swayimg/colors.lua` |
| SwayNC | `~/.config/swaync/colors.css` |
| rofi | `~/.config/rofi/colors.rasi` |
| kitty | `~/.config/kitty/colors.conf` |
| machine-readable palette | `~/.cache/rice/colors.env` |
| Material You base palette | `~/.cache/rice/matugen.env` |
| hellwal base palette | `~/.cache/rice/hellwal/palette.env` |
| ANSI source (wallust fallback) | `~/.cache/rice/ansi-scheme` |
| hyprlock | `~/.config/hypr/hyprlock-colors.conf` |
| GTK 3/4 | `~/.config/gtk-{3,4}.0/gtk.css` |
| vim | `~/.vim/colors/wallust.vim` |
| wlogout | `~/.config/wlogout/colors.css` |
| starship | `~/.config/starship.toml` |
| zsh suggestions/highlighting | `~/.cache/rice/zsh-colors.zsh` |
| btop | `~/.config/btop/themes/wallust.theme` |
| cava | `~/.config/cava/themes/wallust` |
| KDE / Dolphin | `~/.config/kdeglobals` |
| Kvantum | `~/.config/Kvantum/WallustFlat/` |
| Telegram Desktop | `~/.cache/rice/telegram.tdesktop-theme` |
| SDDM | `~/.cache/rice/Colors.qml` → installed theme |
| mode marker | `~/.cache/rice/theme-mode` |
| engine marker | `~/.cache/rice/theme-engine` |
| static theme marker | `~/.cache/rice/theme-name` |

`wall` only lists wallpapers from the current mode directory
(`~/Pictures/walls/light` or `~/Pictures/walls/dark`). Choosing a wallpaper
from the other directory forces that mode; choosing one from the current
directory keeps automatic switching enabled.

Hellwal is the active engine. Matugen (Material You) and the previous wallust
path are wired as alternatives:

```bash
RICE_THEME_ENGINE=matugen wall next
RICE_THEME_ENGINE=wallust wall next
```

Hellwal renders its own 16-colour palette and `rice-contrast` normalizes the
ANSI black/white pair when the engine maps `color0` to the background. Its
colours are image-driven rather than Material roles, so cards and status
colours fall back to the derived semantic palette. Matugen remains the best
choice when role-aware Material surfaces matter more than pure wallpaper
matching.

The matugen scheme type can be overridden without editing the config:

```bash
RICE_MATUGEN_TYPE=scheme-vibrant wall next
```

### Static themes

Static themes ignore the wallpaper. Each theme lives in
`~/.config/rice/themes/<name>/` with a `theme.conf` and one pre-validated
palette per mode:

```text
themes/mclaren/
├── theme.conf     # name, description, wallpaper_root, default_light/dark
├── light.env      # full palette, contrast-checked once
└── dark.env
```

`theme.conf` points at a wallpaper root with `light/` and `dark/`
subdirectories. When a static theme is active, `wall next|prev|random|pick`
chooses from that theme's wallpaper tree instead of
`~/Pictures/walls/{light,dark}`.

Press **`Super+Shift+T`** for the rofi theme picker, or apply a theme directly:

```bash
theme-set mclaren
theme-set mclaren dark
rice-theme --list
```

Static palettes are pre-validated with `rice-contrast --check`. Switching a
theme runs `rice-contrast --trusted`, which renders every template without
re-adjusting the colours. The active theme is recorded in
`~/.cache/rice/theme-name`, and the engine marker is `static`.

Return to wallpaper-derived colours with an explicit engine override:

```bash
RICE_THEME_ENGINE=hellwal wall next
```

The bundled **McLaren F1** theme uses papaya orange, carbon surfaces, and the
wallpapers in `~/Pictures/walls/mclaren/{light,dark}`.

### Contrast and transparency

Terminal transparency stays on, but text must remain readable over whatever
the blurred wallpaper contributes. `rice-contrast` evaluates the
**composited** background (`kitty background_opacity × the minimum Hyprland
active/inactive opacity`, blended with the centre half of the wallpaper), not
just the raw palette background. The policy is role-aware:

| Role | Minimum |
|---|---|
| foreground text | 7:1 |
| ANSI 1–6 and 9–14 | 4.5:1 |
| muted text | 4.5:1 |
| borders and dividers | 3:1 |
| ANSI 0/7/15 black/white pair | 7:1 |

With matugen, ANSI hues are derived from the Material primary: red, green,
yellow, blue, magenta and cyan are fixed semantic hue rotations of the primary,
so they keep their terminal roles while inheriting the wallpaper's saturation
and lightness. With hellwal, the engine's own 16-colour palette is used; if it
maps ANSI black to the light background, `rice-contrast` swaps the black/white
pair back to the terminal convention. Lightness is adjusted in OKLCH; hue is
preserved and chroma is reduced only when a colour would leave sRGB. The stage
also preserves the Material 3 semantic roles (`surface`, `surface_alt`,
`bar_bg`, `muted`, `border`, `accent`, `accent_alt`, `danger`, `success`,
`warning`, `info`, `link`) when matugen supplies them, so cards, menus and bars
follow the Material elevation system instead of reusing ANSI black as a
surface. `rice-contrast --check` prints the measured ratios and exits nonzero
if the palette regresses.

btop reloads live on `SIGUSR2`; cava reloads when its config is touched; an
open vim reloads its colorscheme within two seconds. `theme-apply` sends all
three signals/updates for you. GTK apps cannot reload `gtk.css` in place, so
`theme-apply` restarts the common settings apps (`pavucontrol`,
`nm-connection-editor`, `blueman-manager`, `nwg-look`) automatically; set
`RICE_GTK_RESTART=0` to disable that. GTK theme, icon theme and colour scheme
are switched through `gsettings`; Qt uses `qt6ct` + a generated Kvantum theme
(`WallustFlat`, based on `KvFlat` for dark and `KvArc` for light, with the
active palette baked into the SVG), and vim's `background` is set to match. `kde-theme` also writes
`~/.config/kdeglobals`, so Dolphin's tooltips, icons, selection and view
surfaces follow the same palette.

### What reloads automatically

| App | Behaviour |
|---|---|
| Hyprland, Waybar, SwayNC, kitty | live reload |
| btop | live reload via `SIGUSR2` |
| cava | live reload via `live-config` |
| vim | live reload within 2 s (timer + focus) |
| starship | next prompt |
| rofi, wlogout, hyprlock, swayimg | next time they open |
| Telegram Desktop | live reload via its theme-file watcher |
| SDDM | next greeter start (after install) |
| GTK apps | gsettings theme/icon switch; common settings apps restart automatically, others on next open |
| Qt apps | next open (qt6ct + Kvantum) |
| Chrome | not themed by hellwal; Chrome's own UI theme is separate |

hyprlock uses the current light/dark wallpaper as a blurred background and
adjusts its scrim and clock colour per mode, so the lock screen stays readable
in both palettes.

### Telegram Desktop

Telegram has no public “apply theme” command, so the generated package is
installed into its local profile once:

```bash
# quit Telegram first
telegram-theme --install
telegram-theme --status
```

`--install` writes the theme into `~/.local/share/TelegramDesktop/tdata` and
points both Telegram theme keys (day and night) at the same file, so toggling
Telegram’s own night mode cannot escape the rice palette. `theme-apply` then
rewrites `~/.cache/rice/telegram.tdesktop-theme` on every wallpaper change;
Telegram watches that file and reloads it live. The package also includes a
soft, palette-tinted crop of the active wallpaper as `background.jpg`, so the
chat surface follows the rice instead of Telegram’s default doodle pattern.
`ffmpeg` is used for that background when available; without it the theme
still loads and Telegram keeps its own chat background. The installer needs
`python-cryptography`; day-to-day generation does not. The upstream palette
snapshot is tracked at
`telegram/.local/share/rice/telegram-base.tdesktop-palette`.

Wallpaper binds (always inside the current light/dark mode):

| Keys | Action |
|---|---|
| `Super+F6` | next wallpaper |
| `Super+Shift+F6` | previous wallpaper |
| `Super+F7` | random wallpaper |
| `Super+F8` | pick with thumbnails |
| `Super+Shift+T` | static theme picker |

The chosen wallpaper is also symlinked to `~/.cache/rice/wallpaper`.
`rice-resume` reapplies it after login and sleep, so the selection survives a
reboot without storing a user-specific absolute path in `hyprpaper.conf`.

Add a hook by dropping an executable in `~/.config/rice/hooks/theme-set.d/`.
It receives the image path as `$1` and the palette mode as `$RICE_MODE`.

## Automatic light/dark mode

`rice-mode` computes sunrise/sunset locally with the NOAA solar algorithm. No
network access or extra package is needed after the location is known. The
default location is `28.133528,76.7542707` (the same coordinates as the Waybar
weather module); change it with `rice-mode location LAT,LON` or
`rice-mode location auto`.

| Command | Effect |
|---|---|
| `rice-mode status` | mode, effective mode, sunrise/sunset, next transition, wallpaper |
| `rice-mode auto` | follow sunrise/sunset again |
| `rice-mode light` | force light mode and stop auto switching |
| `rice-mode dark` | force dark mode and stop auto switching |
| `rice-mode toggle` | switch to the opposite forced mode |
| `rice-mode location [LAT,LON\|auto]` | show or change the sun location |
| `rice-mode tick` | apply the current mode (timer entry point) |
| `rice-mode resume` | re-apply at login after hyprpaper starts |

`rice-sun.timer` runs `rice-mode tick` every five minutes. A manual
`light`/`dark`/`toggle` override is persistent until `rice-mode auto` is used
again. The Waybar sun/moon indicator shows the effective mode; left-click
toggles, right-click returns to auto. `rice-resume` runs after login and sleep:
it reapplies the palette, restores the wallpaper, and verifies that Waybar has
a layer on `DP-3` only, recreating it if necessary.

Mode state lives in `~/.cache/rice/`: `mode`, `effective-mode`, `location`,
`wallpaper-light`, `wallpaper-dark`, and `theme-mode`.

### Screenshots and OCR

`rice-screenshot` saves to `~/Pictures/Screenshots` (override with
`RICE_SCREENSHOT_DIR`), copies the image to the clipboard, and offers an
**Annotate** action that opens Satty as a centered floating window. The OCR
mode uses Tesseract with English and Hindi when available, copies the
recognized text, and keeps the source image. It can also be run directly:

```bash
rice-screenshot region
rice-screenshot output
rice-screenshot window
rice-screenshot full
rice-screenshot ocr
```

### Animations

Hyprland uses a Material 3-inspired preset: spring-based window movement,
crisp pop-in/out for windows, slide-fade workspace changes, slide-fade special
workspaces, and fading layers. wlogout is matched on its real `logout_dialog`
layer namespace, so its backdrop is blurred and the overlay fades in; its tiles
also transition and stagger in.

## Health / restart

```bash
rice-doctor                       # health check; exits nonzero on required failures
rice-mode status                  # current mode + sunrise/sunset
systemctl --user list-timers rice-sun.timer
rice-restart                      # restart waybar + swaync + hyprpaper
rice-resume                       # verify/rebuild wallpaper, palette and Waybar
rice-gtk-reload                   # restart running GTK settings apps after a palette change
rice-contrast --check             # verify the generated palette's contrast ratios
rice-keybinds --print             # current bindings without opening rofi
./tests/smoke.sh                  # offline-safe test + isolated Stow restoration
RICE_LIVE_CHECKS=1 ./tests/smoke.sh  # include rice-doctor at the end
```

Both `wall` and `theme-apply` return failure when generation was incomplete;
an optional app reload may still be attempted independently. `theme-mode` is
only marked complete after required generation succeeds, allowing a later
timer tick to retry partial updates.

## SDDM

The custom greeter theme is in `system/sddm/themes/rice/`. It needs `sudo` to
install; see **`system/sddm/README.md`** for install, preview, rollback and
wallpaper-update commands. Once installed with the documented `chown`, SDDM
follows the wallpaper and light/dark palette automatically.

## Recovery

If a lock screen crashes:

```bash
hyprctl --instance 0 eval 'hl.clear_crashed_lockscreen()'
```

If Hyprland misbehaves, switch to a TTY (`Ctrl+Alt+F3`), log in, fix or revert
`~/dotfiles`, then `hyprctl reload`. Every phase is committed; use
`git log --oneline` and `git tag` to return to a known-good state.
